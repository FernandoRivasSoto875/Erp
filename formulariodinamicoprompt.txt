
============================
PROMPT ORDENADO PARA DESARROLLO
============================

1. Reglas generales y arquitectura
----------------------------------
- Archivo de vista/orquestador: solo carga JSON, pasa datos a helpers y renderiza HTML mínimo.
- No lógica de negocio, ni funciones PHP nuevas, ni CSS/JS inline.
- Toda la lógica en helpers (formulariodinamicofunciones.php, formulariodinamicologica.php).
- Sanitizar salida (htmlspecialchars).
- No eliminar ni degradar funcionalidades existentes salvo bug confirmado (usar // DEPRECATED).
- Mantener compatibilidad y no renombrar IDs/clases sin actualizar todas las referencias.
- Mantener modo diseño (toggle + DnD + árbol) operativo.
- Usar solo CSS externo (Bootstrap, etc.), no inline.
- No duplicar includes/requires.
- No dejar salida de depuración permanente.
- No agregar SQL/includes aquí.
- No cambiar el diseño salvo en el contenedor CSS permitido.

2. Requisitos funcionales principales
-------------------------------------
- Soporte para nuevos tipos de campo: "embevido" y "datatable".
- Propiedad "FormularioDataSourcePrincipal" en parámetros del JSON para controlar interacción con BD.
- Datatable debe soportar todas las funcionalidades (búsqueda, filtro, suma, edición, etc.).
- Soporte para todas las características de formularios dinámicos:
  - Tabs anidados
  - Acordeones
  - Wizard/pasos
  - Columnas flexibles
  - Campos condicionales
  - Resumen lateral
  - Vista previa
  - Modo compacto/expandido
  - Drag & drop
  - Temas visuales
  - Mensajes contextuales
  - Integración multimedia
  - Accesibilidad
  - Layouts responsivos
  - Validaciones en tiempo real
  - Campos tipo "fórmula"
  - Búsqueda y suma en datatables
  - Agrupación de filas
  - Acciones masivas
  - Historial de cambios/deshacer

Ejemplo campo "embevido":
{
  "nombre": "contenido_embebido",
  "tipo": "embevido",
  "etiqueta": "Contenido Embebido",
  "url_embebido": "https://www.ejemplo.com/archivo.html",
  "parametros_embebido": { "usuario": "123", "token": "abc" },
  "alto": "400px",
  "ancho": "100%",
  "mostrar_borde": true,
  "permitir_fullscreen": true
}

Ejemplo campo "datatable":
{
  "nombre": "detalle_productos",
  "tipo": "datatable",
  "etiqueta": "Producto",
  "busqueda_simple": "enable",
  "filtro_avanzado": "enable",
  "sumar_columnas": ["precio", "cantidad"],
  "columnas": [
    { "nombre": "producto", "etiqueta": "Producto", "tipo": "text" },
    { "nombre": "precio", "etiqueta": "Precio", "tipo": "number" },
    { "nombre": "cantidad", "etiqueta": "Cantidad", "tipo": "number" },
    { "nombre": "total_linea", "etiqueta": "Total", "tipo": "number" }
  ],
  "dataSource": { "tabla": "" }
}

3. Lineamientos de diseño y UX
------------------------------
- Responsividad y adaptabilidad (Bootstrap, layouts flexibles, barra de scroll horizontal).
- Accesibilidad: navegación por teclado, ARIA, contraste alto.
- Temas visuales configurables desde el JSON.
- Modo diseño siempre operativo (toggle + DnD + edición en árbol y formulario).
- Tooltips y ayuda contextual en encabezados.
- Agrupación de filas por valor de columna.
- Visualización responsiva y adaptable.
- Embellecimiento usando Bootstrap moderno + CSS externo.

4. Validaciones y pruebas
------------------------
- Antes de modificar:
  - Revisar primero lógica existente (formulariodinamico.js, formulariodinamicofunciones.php, arboljson/*).
  - Mantener compatibilidad retro o crear wrapper / alias temporal.
  - No renombrar IDs / clases usadas por JS sin actualizar todo (incluida micro‑app).
  - Mantener contrato JSON (solo ampliar tolerantemente).
  - Eliminaciones: marcar // DEPRECATED si no críticas, conservar breve periodo si hay riesgo.
  - Sin echo/print debug permanentes.
  - Sin SQL / includes extra aquí.
  - Evitar duplicar includes/require.
  - Sanitizar salida (htmlspecialchars) siempre.
  - Commits/PR atómicos (render / JS / CSS / refactor / integración árbol).
  - Integración árbol: aquí solo contenedor #fd-json-tree-app (no markup interno).
  - CONSISTENCIA DE LLAMADOS: verificar includes, data-* (#fd-data), scripts (Sortable + formulariodinamico.js), contenedor micro‑app y funciones clave (fd_render_layout_fallback) existen y JSON decodifica (json_last_error()==JSON_ERROR_NONE).
  - Modo diseño debe seguir operando (toggle + DnD + árbol) tras cualquier cambio.
  - NO cambiar el diseño a no ser que sean cambios en <div class="css"></div>

- Al finalizar:
  - Verifica que todo quede de forma responsiva.
  - Si hay algo que no puedes hacer por restricción del prompt, indícalo y sugiere qué agregar.

5. Nuevas funcionalidades y extensiones
--------------------------------------
- Micro‑app encapsula HTML/CSS/JS para explorar / editar parámetros, fieldsets y layout.
- Integración: contenedor #fd-json-tree-app (iframe o montaje dinámico).
- Comunicación: postMessage, namespace FD, o endpoints AJAX.
- Separación de modos y funcionalidades:
  - "Diseño Árbol": editar estructura desde el árbol JSON y arrastrar objetos en el formulario.
  - "Diseño Formulario": editar directamente el formulario con DnD y arrastrar objetos.
- Modo diseño (siempre activable/desactivable).
- Rediseño en tiempo de ejecución por el usuario final, manteniendo estricta separación de responsabilidades, UX moderna y edición visual/estructural robusta, sin perder ninguna funcionalidad existente.
